## 3. Disable simulation during normal operation

Disable runtime simulator ingestion by default.

Requirements:

- No simulated devices are created during ordinary startup.
- No simulated observations are generated by background workers.
- No synthetic measurements appear in live API responses.
- No simulator updates are broadcast through SignalR.
- No periodic simulator job continues consuming resources.
- Normal operation does not require the simulator to exist.

If the simulator remains available for development:

- Make it explicitly opt-in.
- Keep it disabled in normal Development and Production configurations.
- Document how to enable it in an isolated test environment.
- Do not automatically enable it when no providers are configured.
- Do not use it as a fallback when provider data is unavailable.

Prefer removing unnecessary runtime registration rather than introducing complex new configuration.

Preserve simulator fixtures needed by automated tests.

## 4. Safe cleanup of existing simulator data

Implement a dedicated, explicit, opt-in cleanup command.

The command must support:

- Read-only dry-run by default.
- Explicit execute mode.
- Property-scoped execution.
- A separate explicit confirmation argument for destructive operations.
- Detailed counts of affected records.
- Identification of dependencies before deletion.
- Safe handling of foreign keys.
- Bounded transactions where necessary.
- Clear error reporting.
- An auditable summary of the cleanup.

Suggested conceptual command:

`--cleanup-simulator-data --property=N`

Actual argument names should follow existing CLI conventions.

Never execute destructive cleanup automatically at startup or during database migration.

### Data to investigate

## Execution summary

**Simulator dependencies found**
- **Writer:** `Simulator:Enabled` was on by default, so `TelemetryWorker` wrote six demo devices into the seeded Countryside House property every 10 s and broadcast SignalR updates.
- **Simulator-only readers:** `/state`, `/devices` and `/history` (`MonitoringReader`) served only simulator devices and series. These fed the Devices cards and the Energy page, and `/system/health` gave Energy the simulator's cadence.
- **Mixed readers:** the dashboard catalog, 7A and logical history, 7B initialization and 7E provisioning all included simulator data.

**Runtime changes**
- The simulator is off by default in code and in configuration.
- **Readers:** state, devices and history now serve real-provider devices and series, with freshness from the 7A hold policy; separate streams are never merged. Simulator series and sources are hidden from the dashboard catalog and every history read unless the simulator is enabled.
- **Logical devices:** simulated hardware is skipped by initialization and provisioning and cannot be newly assigned.
- **Energy page:** drops the simulator-only counter card and uses provider series with Growatt's cadence and truthful empty states.
- The simulator code stays for development and tests.

**Cleanup**
- The command is `--cleanup-simulator-data --simulator-property=<id>`. It is a dry run by default; `--execute --confirm-simulator-data-deletion` deletes, and it refuses while the simulator is enabled.
- **Ownership by provenance:** the simulator connection, `simulator:` inventory keys and the `simulator` source key. Mixed devices, logical identities with real hardware, the simulated hardware they reference, and simulator series on kept hardware are all preserved and reported.
- **Execution:** samples go in resumable batches of 5,000, then one structural transaction under the property and rollup locks re-plans and deletes in foreign-key order. It refuses stale plans.
- **Never touched:** dashboard layouts (references are reported only), seeded rows, users, the vault and grants.
- It adapts to schemas without the 011 or 017–019 tables.
- **Permissions:** `SELECT, DELETE` plus `UPDATE` on `properties`. No migration.

**Verification**
- **Backend:** Release build passed with zero warnings. Tests reported 320 passes and 11 opt-in skips with disposable MySQL 8.0.46 fixtures, twice in a row; without fixtures, 293 passes and 38 skips.
- **CLI smoke on the disposable server:** dry run, least-privilege execution, idempotent rerun, and refusal with the runtime account.
- **Frontend:** production build passed and Vitest reported 93 passes.
- **Not touched:** the live database, the running backend, the providers and the devices.
