# Growatt read-only integration

## Decision

Keep the simulator running. The Growatt dashboard panel is wired to a separate, property-scoped data source. This milestone supplies normalized read contracts, identity and telemetry mapping, polling, persistence and fixtures. Live activation requires an authorized transport implementation and an SPF 5000 ES contract that can be tested against both installed devices.

At this property ShinePhone shows two SPF 5000 ES inverters, Master and Slave, with approximately 4 kWp of PV, one shared 51.2 V / 200 Ah BMS-managed battery, and grid input through an external ATS. The account currently has no API token exposed. Neither the account entitlement nor firmware-specific telemetry has been verified.

## Enablement prerequisites

1. Ask [Growatt regional support or the installer](https://en.growatt.com/support/contact) to confirm the registered region, eligible account role, available read-only access, plant approval, coverage for both SPF 5000 ES serials and firmware versions, and credential lifecycle.
2. Obtain the authorized read contract and sanitized discovery/status responses for both inverters. Confirm capability, units, scale, sign, timestamp and freshness semantics, measurement boundaries, errors, rate limits, and whether requests replay cached observations. Verify which measurements are installation totals versus independent readings and which inverter is authoritative for the shared battery.
3. Implement and register an authorized `IGrowattReadSource`. Keep external DTOs, region routing and credentials in Infrastructure. Use a backend secret source for credentials. The source must honor cancellation, apply vendor limits per actual request and translate throttling responses into a retry delay when supplied. The released application contains no live transport or credentials to configure yet.
4. Set `Growatt__Enabled=true` only with that source registered. Set `Growatt__SiteKey` to an existing property key (the demo seed uses `countryside`), `Growatt__MasterId` and `Growatt__SlaveId` to the confirmed external IDs, and `Growatt__BatterySourceId` to the nominated inverter. Property membership gates the read panel. Devices have separate Growatt identities and a separate installation in the property. Review existing bindings before changing mapped IDs or roles.
5. Set `Growatt__PollSeconds` (default 300, range 30–1800), `Growatt__TimeoutSeconds` (default 15, positive and shorter than polling), and `Growatt__FreshnessSeconds` (default 900, at least twice polling and at most 86400). Use the measured logger cadence and authorized API quota. Disabled is the default. An enabled configuration with no registered transport reports that state and performs no Growatt I/O.

## Mapping and operating behavior

- The adapter boundary takes normalized reports. Fixtures represent that internal contract without implying vendor JSON fields. Individual measurements include AC input voltage/frequency, grid import and availability when reported, PV voltage/power, load, mode, warning code, and device fault/connectivity. Shared battery values include voltage, SOC, and signed power (positive charging). A counter can be stored as an absolute reading where its semantics are verified.
- A dedicated battery endpoint accepts only the nominated source. Missing readings stay missing and prior readings age out. The installation prefers explicitly scoped totals. Optional `Growatt__SumIndependentPv` sums two fresh, equal-timestamp individual readings only when independently measured. Optional `Growatt__MasterReportsWholeSiteLoad` copies a confirmed whole-site master reading once. Both options default to false. Input voltage, inverter mode, loss of cloud and import power do not independently establish grid or ATS state.
- Use provider observation times for freshness and ordering. Keep receipt time in the telemetry tables. Invalid timestamps, duplicate mapped inverter reports and invalid scope/type fail validation before writes. During outages retain stored history and let previously reported status age to unknown. Explicit device offline/fault reports remain distinct from provider failures.
- The worker settles one poll before scheduling another. Per-connection cadence, timeout, exponential recovery deferral and a delayed probe after repeated failures bound provider pressure. Server-provided retry delays take precedence. Simulator ingestion has its own worker, identities and telemetry source. Growatt uses existing MySQL tables and the capability model. No schema migration is needed for this milestone.
- The authenticated dashboard shows a separate Growatt panel. Its disabled status has no fabricated readings. Tests use synthetic reports and injected read/store ports. Real grid-power state, measurement meaning and cloud access remain commissioning checks.
